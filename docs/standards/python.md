# Python

## TL;DR

- Python **3.12 or newer**, declared in `requires-python`.
- **uv** manages Python, environments and dependencies. `uv.lock` is committed. `pyproject.toml` is the only configuration file.
- **Ruff** lints and formats (line length 100). **mypy** checks types: strict for new code, with documented exceptions for old code.
- **pytest** + **pytest-cov**. Tests live in `tests/unit`, `tests/integration`, `tests/e2e`, outside the package. Calls to LLM and embedding providers are **always mocked** in CI.
- `logging`, never `print`. Configuration through `pydantic-settings` and environment variables, validated at startup.

Start from the template: [`templates/python/pyproject.toml`](../../templates/python/pyproject.toml).

## Project setup in 5 commands

```bash
uv init --package --name my-package        # new project with src/ layout
cp <engineering-standards>/templates/python/pyproject.toml .   # then fill the TODO markers
uv add fastapi pydantic-settings           # runtime dependencies
uv add --dev ruff mypy pytest pytest-cov   # development tools (dev group)
uv run pytest                              # uv creates .venv and installs everything
```

## Rules

### PY-001: The project supports Python 3.12 or newer

**MUST** · Level 1 · Verified by: `python-version` input of `python-ci.yml` (automatic); code review of `pyproject.toml` (manual)

- `pyproject.toml` declares `requires-python = ">=3.12"` (or a newer minimum).
- `.python-version` is committed and contains the version used for development (`3.12`).
- Ruff's `target-version` matches the minimum (`py312`).

**Why:** 3.12 is the common base of DAH Labs projects. It brings better error messages, `type` statements and faster code. A higher minimum (3.13) is allowed when a project needs it.

### PY-002: uv manages environments and dependencies, and `uv.lock` is committed

**MUST** · Level 1 · Verified by: `uv sync --locked` in `python-ci.yml` fails when the lock file is missing or outdated (automatic)

- Install: `uv sync`. Add a dependency: `uv add <package>`. Run a tool: `uv run <command>`.
- `uv.lock` is committed and updated in the same PR as `pyproject.toml`.
- CI installs with `uv sync --locked`, so the exact versions of the lock file are used.
- `[tool.uv] required-version` pins a minimum uv version for everyone.
- Do not use `pip install`, `poetry`, `conda` or `requirements.txt` to manage the project.

**Why:** one tool, one lock file: every contributor and CI get the same versions. uv is also much faster than pip, which matters on slow connections. See [ADR 0004](../adr/0004-uv-for-python-projects.md).

**Examples:**

- ✅ `uv add httpx` (updates `pyproject.toml` and `uv.lock` together)
- ❌ `pip install httpx` in the project environment (the lock file does not know about it)

### PY-003: `pyproject.toml` is the single source of configuration

**MUST** · Level 1 · Verified by: code review (manual); audit checklist (manual)

All project metadata and tool settings (Ruff, mypy, pytest, coverage, import-linter) live in `pyproject.toml`. The repository has no `setup.py`, `setup.cfg`, `pytest.ini`, `.flake8`, `mypy.ini` or `tox.ini`.

A `requirements.txt` file MAY exist **only** if it is generated by `uv export` (for a tool that cannot read `uv.lock`), with a comment at the top that says so.

### PY-004: Ruff lints and formats all Python code, with a line length of 100

**MUST** · Level 1 · Verified by: `ruff check` and `ruff format --check` in pre-commit and `python-ci.yml` (automatic)

Ruff replaces black, isort, flake8, pyupgrade, pydocstyle and the basic bandit checks. There is no other formatter or linter for Python. See [ADR 0003](../adr/0003-ruff-for-linting-and-formatting.md).

```bash
uv run ruff check --fix .   # lint and fix what can be fixed safely
uv run ruff format .        # format
```

### PY-005: Level 1 enables at least the base rule set

**MUST** · Level 1 · Verified by: code review of `[tool.ruff.lint]` (manual); `ruff check` (automatic)

The base rule set is `E`, `W`, `F`, `I`, `UP`, `B`, `S` and `T20`. It finds real bugs, unused code, security problems and `print()` calls, and existing code can adopt it quickly.

### PY-006: Level 2 enables the full DAH Labs rule set

**MUST** · Level 2 · Verified by: code review of `[tool.ruff.lint]` (manual); `ruff check` (automatic)

The full rule set is the one of the template. Each family is explained in the template comments:

| Code | Plugin | Why we enable it |
|---|---|---|
| `E`, `W` | pycodestyle | Basic style errors |
| `F` | Pyflakes | Unused imports and variables, undefined names |
| `I` | isort | One import order everywhere |
| `N` | pep8-naming | `snake_case` functions, `PascalCase` classes |
| `UP` | pyupgrade | Modern syntax (`list[str]`, `X \| None`) |
| `B` | bugbear | Likely bugs (mutable default arguments…) |
| `S` | bandit | Security: `eval`, weak hashes, hard-coded passwords, `subprocess` with shell |
| `C4` | comprehensions | Simpler comprehensions |
| `SIM` | simplify | Simpler conditions |
| `PT` | pytest-style | Consistent pytest code |
| `RUF` | Ruff | Ruff-specific checks, including unused `noqa` |
| `PGH` | pygrep-hooks | No blanket `# noqa` or `# type: ignore` |
| `PLC`, `PLE`, `PLR`, `PLW` | Pylint | Too many arguments, branches, returns; magic values |
| `C90` | mccabe | Cyclomatic complexity at most 10 |
| `D` | pydocstyle | Google-style docstrings on public code (PY-011) |
| `T20` | print | No `print()` (PY-019) |
| `ERA` | eradicate | No commented-out code |

In `tests/`, `S101` (assert), `PLR2004` (magic values) and `D` (docstrings) are disabled.

**FastAPI:** do not disable `B008` globally. The template lists `fastapi.Depends`, `Query`, `File`… in `extend-immutable-calls`, so only FastAPI's pattern is allowed.

**How to move from Level 1 to Level 2 on existing code:** enable one family per PR, run `ruff check --fix`, fix the rest by hand, and add a temporary `per-file-ignores` entry with an issue number for files that need a real refactoring.

### PY-007: Every `noqa` names the rule and gives a reason

**MUST** · Level 1 · Verified by: Ruff `PGH004` and `RUF100` (automatic); code review (manual)

- ✅ `subprocess.run(cmd, check=True)  # noqa: S603 - cmd is a fixed list, no user input`
- ❌ `subprocess.run(cmd, shell=True)  # noqa`

### PY-008: Public functions, methods and classes have type annotations

**MUST** · Level 2 · Verified by: mypy `strict` (`disallow_untyped_defs`) in `python-ci.yml` (automatic)

Every public function has annotated parameters and return type. Prefer precise types (`list[Document]`, `Literal["free", "hybrid", "premium"]`) to `Any`.

```python
# ✅
def embed(self, texts: list[str]) -> list[list[float]]: ...


# ❌
def embed(self, texts): ...
```

### PY-009: mypy runs in strict mode on new code, with documented overrides for old code

**MUST** · Level 2 · Verified by: `mypy` in `python-ci.yml` (automatic); review of `[[tool.mypy.overrides]]` (manual)

`[tool.mypy] strict = true` is set for the whole project. Modules that are not typed yet get an override that relaxes **only** the checks they fail, with an issue number:

```toml
[[tool.mypy.overrides]]
module = ["rag.retrieval.legacy_bm25"]  # TODO: remove, issue #87
disallow_untyped_defs = false
```

**How to become strict progressively:**

1. Enable `strict = true`. Run `uv run mypy src` and count the errors per module.
2. Add an override for every module with errors. CI is green again.
3. Each PR that touches a module with an override types that module and removes its override.
4. New modules never get an override.
5. The number of overrides only goes down. Check it in each audit.

**Why:** types catch errors before runtime and document the code. Strict mode on new code costs little; asking for it on old code all at once blocks everybody. See [ADR 0006](../adr/0006-mypy-strict-progressive.md).

### PY-010: The whole code base passes mypy strict without overrides

**SHOULD** · Level 3 · Verified by: no `[[tool.mypy.overrides]]` that relaxes checks on project modules (manual)

Overrides for untyped third-party libraries (`ignore_missing_imports`) are still allowed.

### PY-011: Public API has Google-style docstrings

**MUST** · Level 2 · Verified by: Ruff `D` rules with `convention = "google"` (automatic)

def retrieve(self, query: str, top_k: int = 5) -> list[ScoredDocument]:
    """Return the documents most relevant to a query.

### PY-012: Tests live outside the package, in `tests/unit`, `tests/integration` and `tests/e2e`

**MUST** · Level 1 · Verified by: code review (manual); audit checklist (manual)

```text
backend/
├── src/my_package/        # code only
└── tests/
    ├── conftest.py        # shared fixtures
    ├── unit/              # fast, no network, no service
    ├── integration/       # real database, queue or container
    └── e2e/               # the whole application, through its API
```

- ✅ `backend/tests/unit/test_chunker.py`
- ❌ `backend/src/tests/test_chunker.py` (tests are shipped with the package and import it as `src.…`)

### PY-013: Tests use pytest, pytest-cov and declared markers

**MUST** · Level 1 · Verified by: `--strict-markers` in `[tool.pytest.ini_options]` (automatic); `python-ci.yml` (automatic)

Declare markers in `pyproject.toml`. An undeclared marker is an error.

| Marker | Meaning | Runs in CI by default? |
|---|---|---|
| `slow` | Takes more than 1 second | yes, but not in the pre-push hook |
| `integration` | Needs a database, a queue or a container | in a separate job (PY-025) |
| `requires_gpu` | Needs a GPU | never (GitHub-hosted runners have no GPU) |
| `requires_api_key` | Calls a paid or rate-limited API | never |

The default marker expression of `python-ci.yml` is `not slow and not integration and not requires_gpu and not requires_api_key`.

### PY-014: Tests are named `test_<unit>_<expected_behavior>` and follow Arrange-Act-Assert

**SHOULD** · Level 1 · Verified by: code review (manual)

```python
def test_chunker_keeps_overlap_between_chunks() -> None:
    # Arrange
    chunker = BasicChunker(chunk_size=10, chunk_overlap=3)

    # Act
    chunks = chunker.split("abcdefghijklmnop")

    # Assert
    assert chunks[1].text.startswith(chunks[0].text[-3:])
```

- ✅ `test_factory_rejects_unknown_embedder_type`
- ❌ `test_1`, `test_factory`, `test_it_works`

### PY-015: Unit tests are fast, deterministic and offline

**MUST** · Level 1 · Verified by: CI runs without network secrets (automatic); code review (manual)

A unit test:

- runs in less than 100 ms;
- gives the same result every time: fixed random seeds, frozen time, sorted outputs;
- does not use the network, a database, a GPU or files outside `tmp_path`.

Projects MAY add [pytest-socket](https://github.com/miketheman/pytest-socket) with `--disable-socket` on `tests/unit` to enforce the "offline" part.

### PY-016: Calls to LLM and embedding providers are mocked in CI

**MUST** · Level 1 · Verified by: CI has no provider API key (automatic); code review (manual)

CI never calls OpenAI, Mistral, Cohere, Gemini, Hugging Face Inference or any paid API. Use one of these approaches:

1. **A fake adapter** that implements the port (the best option, because the architecture already allows it):

   ```python
   class FakeLLM(ILLM):
       def __init__(self, answer: str) -> None:
           self.answer = answer
           self.prompts: list[str] = []

       def generate(self, prompt: str) -> str:
           self.prompts.append(prompt)
           return self.answer
   ```

2. **HTTP mocking** with [respx](https://lundberg.github.io/respx/) (httpx) or `unittest.mock`.
3. **Recorded responses** with [pytest-recording](https://github.com/kiwicom/pytest-recording) (vcrpy). Cassettes are reviewed before commit: they MUST NOT contain API keys, tokens or personal data. Configure `filter_headers=["authorization", "x-api-key"]`.

Tests that really call a provider are marked `requires_api_key` and run only by hand.

**Why:** no surprise cost, no flaky test because a provider is slow, and contributors without API keys can run every test.

### PY-017: CI measures coverage and the global threshold never goes down

**MUST** · Level 2 · Verified by: `coverage-fail-under` input of `python-ci.yml` (automatic)

1. Measure today's total coverage: `uv run pytest --cov`.
2. Set `coverage-fail-under` to that value, rounded **down** to the nearest integer.
3. Raise the value when coverage goes up. Never lower it.

Coverage of **new code** is checked by SonarQube Cloud, with a target of **80 %** (see [SonarQube Cloud](sonar.md)).

**Why:** a global target of 80 % on day one would block every PR of a project at 35 %. A threshold that only goes up, plus a strict rule on new code, improves coverage with each PR.

### PY-018: Total coverage is at least 80 %

**SHOULD** · Level 3 · Verified by: `coverage-fail-under: 80` in CI (automatic)

### PY-019: Code uses `logging`, never `print`

**MUST** · Level 1 · Verified by: Ruff `T20` (automatic)

```python
import logging

logger = logging.getLogger(__name__)


def load(path: Path) -> list[Document]:
    logger.info("Loading documents", extra={"path": str(path)})
```

Command line scripts in `scripts/` MAY use `print` for their output. Projects MAY use [structlog](https://www.structlog.org/) (baraza does) for structured logs.

### PY-020: Logs contain no secrets and no personal data

**MUST** · Level 1 · Verified by: code review (manual)

Never log API keys, tokens, passwords, full request headers, user messages, transcripts or e-mail addresses. Log identifiers and sizes instead.

- ✅ `logger.info("LLM call", extra={"provider": "mistral", "prompt_tokens": 812})`
- ❌ `logger.debug(f"Calling {url} with headers {headers} and prompt {prompt}")`

### PY-021: Configuration uses `pydantic-settings`, environment variables and validation at startup

**MUST** · Level 1 · Verified by: code review (manual)

- Settings are read from environment variables (and an optional `.env` file for development) with [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).
- Invalid or missing settings stop the application **at startup**, with a clear message.
- Every variable is listed in `.env.example`, with a safe example value and a comment.
- Complex, versioned configuration (pipelines, experiments) MAY use YAML files validated by Pydantic models, as RAG-DataAfriqueHub does for its free, hybrid and premium modes.

```python
from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="BARAZA_", env_file=".env")

    database_url: str
    llm_api_key: SecretStr | None = None  # SecretStr is hidden in logs and repr()
    cors_origins: list[str] = ["http://localhost:3000"]
```

### PY-022: The code lives in `src/<package_name>/` and the package has a real name

**MUST** · Level 1 · Verified by: code review (manual)

- The import name is the project name in `snake_case`: `import baraza`, `import dah_rag`.
- The package is never named `src`. `from src.core import factory` is not allowed.
- The distribution name (`[project] name`) and `description` are real values, not `backend` or "Add your description here".

**Why:** with the `src/` layout, tests run against the installed package, not against files that happen to be in the current directory. A real name avoids conflicts and makes imports readable.

### PY-023: Runtime and development dependencies are separated

**MUST** · Level 1 · Verified by: code review of `pyproject.toml` (manual)

`[project] dependencies` lists what the application needs to run. Test, lint and type tools go in `[dependency-groups] dev`. Optional features (GPU, notebooks) go in `[project.optional-dependencies]`.

- ✅ `pytest` in `[dependency-groups] dev`
- ❌ `pytest` and `pytest-cov` in `[project] dependencies` (they are installed in the production Docker image)

### PY-024: `pyproject.toml` gives lower bounds; exact versions live in `uv.lock`

**SHOULD** · Level 1 · Verified by: code review (manual)

Write `"fastapi>=0.161"`, not `"fastapi==0.161.1"`. Add an upper bound only for a known incompatibility, with a comment. Dependabot updates both files.

### PY-025: Integration tests that need services run in their own CI job

**SHOULD** · Level 2 · Verified by: CI workflow review (manual)

The reusable `python-ci.yml` runs unit tests. A project with Postgres, Redis or another service adds a job in its own workflow, with `services:` and `pytest -m integration`. baraza's CI is a good example.

## Checklist

- [ ] `requires-python = ">=3.12"` and `.python-version` are present.
- [ ] `uv.lock` is committed and CI runs `uv sync --locked`.
- [ ] There is no `setup.py`, `setup.cfg`, `pytest.ini`, `mypy.ini` or hand-written `requirements.txt`.
- [ ] Ruff lint and format pass with `line-length = 100` and at least the Level 1 rule set.
- [ ] mypy runs in strict mode; every override has an issue number (Level 2).
- [ ] Tests are in `tests/unit`, `tests/integration`, `tests/e2e`; markers are declared.
- [ ] No test calls a paid API; providers are faked or mocked.
- [ ] CI fails below the coverage threshold, and the threshold never went down (Level 2).
- [ ] No `print()` in the package; no secret in logs.
- [ ] Settings use `pydantic-settings` and `.env.example` is complete.
- [ ] The package is in `src/<real_name>/`; test tools are not runtime dependencies.
